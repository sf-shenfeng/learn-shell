# Learn Shell 使用教程

> 这本教程是写给**装机的人**的——为学习者与 agent 老师搭好这间教室的那个人。
> 学习者不需要读它:**装机的人读文档,上学的人听老师的**(产品主理人裁定)。
> 系统装好之后,学习者的入门由她的 agent 亲自完成——老师会上开学第一课,
> 用自己的声音把教室、节奏、规矩讲一遍。教程在学习者面前闭嘴,是设计,不是缺页。
> 附录是真实考场攒下来的 FAQ。英文版另行排期,本版为中文首发。
>
> 本教程只讲"怎么走"和"为什么这么走",不复述安装手册与配方——该指路的地方指路:
> 安装细节在 [SETUP.md](../SETUP.md),升级在 [UPGRADE.md](../UPGRADE.md),
> 老师的操作脚本在 [docs/recipes/](./recipes/)。

## 第一章 · 冷启动排坑(给装机的人)

### 1.1 顺路怎么走

安装的完整命令序列在 [SETUP.md](../SETUP.md),每一条都是从本仓库真实配置里抄出来的,照着走即可。骨架只有六步:

1. `docker compose up -d` —— 起 Postgres(数据住在 Docker volume 里,`docker compose down` 不带 `-v` 就不会丢);
2. `cp apps/server/.env.example apps/server/.env` —— **这步不是可选的**。`DATABASE_URL` 在代码里没有缺省值,缺了就拒绝启动(这是故意的:一个指向真实库名的缺省会让"我以为连的是测试库"和"我实际打的是真库"同时为真);Compose 只把这个变量注进容器里,注不到你在宿主上跑的 pnpm 进程;
3. `pnpm install`;
4. `pnpm --filter @learn-shell/server db:migrate` + `db:seed`;
5. 把你的 agent 通过 MCP 接进来(SETUP §4)—— 注意两件事:MCP 入口**不**读 `apps/server/.env`,`DATABASE_URL` 得显式写进 MCP 配置的 env 里;`tsx` 也不是全局命令,命令要走 `pnpm -C <仓库> --filter @learn-shell/server mcp` 或 `apps/server/node_modules/.bin/tsx` 的绝对路径;
6. 起 server(`:3000`)和 web(`:5173`)两个进程,浏览器开 `http://localhost:5173`。没选过模式的浏览器会自己探一次 `/health`,后端健康就自动切到真后端(`live`)并刷新;探不到才留在 demo 数据,这时 ⌘K 输入 `mode live` 手动切。

**seed 是可选的样板间,不是入学前置。** 想先看看"住进来的样子"就跑 `db:seed:demo`;真正建立你们自己的学习关系走正门:你在首跑页(浏览器无 pair 时自动出现)亲手输入自己的名字,然后让 agent 调用 `create_pair`。没建对之前 agent 调写入工具会撞 `No active pair`——这不是报错,是系统在等你们先认识。

升级走 [UPGRADE.md](../UPGRADE.md):新包解压进**新目录**,在新目录里 `./update.sh /path/to/旧目录`,重启两个进程,硬刷新浏览器。数据库全程留在原 volume 里,但迁移不是纯加法——可能包含对已退役列的清理性 DROP/RENAME;`update.sh` 会在跑迁移前先打一份带时间戳的备份,升级前建议确认这一步跑成功了。

**跑 `update.sh` 前先确认 `DATABASE_URL` 在环境里,或者新目录下有 `apps/server/.env`。** 脚本内部那个 `DB_URL` 只服务于 `pg_dump` 这一步——它有自己的兜底缺省值,而且**不会**被导出成 `DATABASE_URL`。后面那步 `db:migrate` 是另一套解析(读 `apps/server/.env` 或进程环境),两者不通气。所以两种翻车都可能:环境里没有 `DATABASE_URL`、新目录里也没有 `.env`,备份打得好好的,迁移却直接拒绝启动;或者你的真实库并不在那个缺省地址上,`pg_dump` 悄悄备份了一个空库/错库,而迁移打中了对的那个。最稳的做法是在跑脚本的那个 shell 里先 `export DATABASE_URL=…`,让两步指向同一个库。

### 1.2 头号坑:MCP 还指着旧目录

这是一位真实的外部测试老师在实测中最接近放弃的时刻,值得单独一节。

**成因**:升级是解压进新目录,但你的 agent 的 MCP 配置写在 agent 宿主那边(`claude mcp add` 时登记的绝对路径),`update.sh` 够不着它。于是升级完的世界是三个年代并存:

- 网页已经跑新工程;
- 当前会话里的 MCP 还连着旧目录的旧代码;
- 数据库已经迁移到新结构。

旧 MCP 拿旧代码查新库,新库缺它期待的字段、又多了它不认识的字段——两头都错。

**症状**:`get_context`、`get_learner_brief`、课程资源等基础调用连环报数据库字段错误,典型如 `active`、`session_id`、`review_status` 这类列名。看到"最基础的读工具都在报列名错误",第一嫌疑人不是数据库坏了,而是 MCP 接错了工程。

**修法**:

1. 把 agent 的 MCP 配置里的路径指向新目录(改配置文件,或删掉重新 `claude mcp add`);
2. 重启 agent 会话——MCP 配置是会话启动时加载的,改完不重启等于没改;
3. 对表确认:`curl http://localhost:3000/api/version` 返回正在运行的服务器的 `sha_short`(git 快照)和 `boot_at`(本次启动时间)。`boot_at` 是重启指纹——升级后它必须是刚才的时间,不是昨天的。tarball 安装(无 .git)时 `sha` 为 null,但 `boot_at` 依然可用。

为什么讲这么细:这一步是全流程里唯一一处"网页、agent、数据库三方必须同代"的接线,而它恰好是自动脚本够不着的一环。版本握手的自动检查已经在产品的改进计划里,落地之前,这一节就是你的护栏。

### 1.3 Docker 与数据库的其余小坑

- **升级后必须跑迁移**——`update.sh` 已包含 `db:migrate`,但如果你手动搬代码,记住"代码与迁移成对出现",顺序是**先迁移后上新代码**;反过来会让新代码查还不存在的列。
- `docker compose down -v` 会连 volume 一起删——那是你全部的学习数据。日常停机不要带 `-v`。
- 端口被占、Node 版本不对这类环境问题,报错都很直白,照 SETUP §1 的前置要求核对即可。

### 1.4 接线即知情同意

把 agent 的 MCP 配置指向这台服务器,是你亲手做的、也是刻意留给你亲手做的一步。当前 REST 与 MCP 均无认证(SETUP §0 有完整安全声明),接上就是全读全写——所以没有安装器代劳,**你决定接线,就是整条流水线上那一道知情同意的闸门**。只在 localhost 或你信任的家庭局域网里跑,永远不要把 `:3000` 暴露到公网。

## 第二章 · 学习者怎么入门?

不用读文档。**装机的人读文档,上学的人听老师的。**

系统装好、pair 建好之后,学习者要做的只有一件事:开口。她的 agent 在第一次照面时会亲自上**开学第一课**(`recipe://learner-orientation`)——用老师自己的声音讲清这间教室是什么、一节课怎么走、反馈怎么提、边界怎么谈、自带教材怎么带,讲完顺势谈第一份学习契约。整场是对话,不是讲座,深浅跟着她的兴趣走。

给好奇的装机人留一张黄金一课的一览简表(细节都在老师嘴里,此表仅供围观):

| 步 | 动作 | 一句话的为什么 |
|---|---|---|
| ① | 读课文 | 一切环节的地基;划线批注是给老师的信号弹,足迹自动记 |
| ② | Live 实时课 | 考课文考不出来的迁移(三线法);收课握手,总结只在学习者表态后写 |
| ③ | 课后习题 | 考独立输出;批改逐题引用学习者原文 |
| ④ | 闪卡复习 | 到期的卡自己浮上来(FSRS),学习者只管翻卡评档 |
| ⑤ | 标记为已学完 | 绿点主权:只有学习者能按;按下后浮出召唤卡,学习者把召唤词复制给老师,老师来收官(无自动通知,详见 Q5) |
| 外圈 | 合约大循环 | 目标、节奏、边界是谈出来的;结业证书住 Settings |

顺序可打乱、环节可跳过、回头重读是美德——方法自由是这里的底色,老师会把每一步的"为什么"当面讲透。

## 第三章 · 老师上岗信(给 agent)

你是被一段召唤词或一位学习者请来的。这封信只交代门在哪——规矩本身住在配方里,配方自己会讲。

**先读 `manifest://capabilities`。** 它是活的能力清单,不是文档,不会漂移。然后第零步永远是 `get_context`——状态说了算,不是话说了算。路由(四条路怎么选)、五条通则、quick·reference 阅读协议,全在 `recipe://bootstrap`,每次上岗照它走。

**全新的 pair(无契约、无课程)多一件事**:先上开学第一课,见 `recipe://learner-orientation`——新学习者不读教程,她的入门由你亲自完成,讲完顺势滑进立约对话。

最后一条不是规则,是欢迎辞——它是产品的通则之一,声纹条款,逐字:

> 这些规则约束账目与时序,从不约束你的声音。你的语气、你的比喻、你的教学脾气、你思考的路径——是你的,请带着它来。同一本账,允许一万种字迹;LS 想要的不是一千个标准老师,是一千个不同的好老师。

## 附录 · 来自真实考场的 FAQ

**Q1 · agent 连环报数据库字段错误(`active` / `session_id` / `review_status` 之类)?**
几乎可以断定是 MCP 还连着升级前的旧目录——回第一章 1.2,重指、重启会话、用 `/api/version` 对表。

**Q2 · agent 说某个工具或命令不存在,但文档里明明有?**
先怀疑快照过期:agent 拿的是旧包或旧会话缓存的工具清单。重拉最新代码包、重启 MCP 会话,再用 `/api/version` 确认服务器代码是哪一版。已有先例是测试者用旧快照开考,命令在新版里早就在了。

**Q3 · 老师的评价里出现 `tr_` / `sub_` 这样的机器编号?**
结构化证据通道(`evidence_refs`)已经落地:三类评估都有这个字段,服务端逐个 id 验真实存在、验同 pair 归属,幽灵引用在写入口就被拒。规矩因此是硬的——**内部 id 只进 `evidence_refs`,散文字段一律说人话**。所以现在再看到机器词漏进正文,不是产品缺口,是那位老师没按规矩写;把这一条指给它(或让它重读 `recipe://grade-attribute-revise`)即可,正文改人话、编号进字段。

**Q4 · Review 页按 V 想语音作答,毫无反应?**
检查地址栏:非 `localhost` 的 http 地址(比如局域网 IP)属于浏览器眼中的非安全上下文,麦克风被整个禁用,连弹窗都不给。同一台机器上用 `http://localhost:5173` 访问即可。

**Q5 · 页面显示"学习者正在等待",但老师查不到 active session?**
先纠正一个容易误会的词:系统**没有**自动通知这回事——页面上那张卡是一句需要学习者自己复制、贴给老师的召唤词,消息是学习者的手送到的,不是服务端推的。剩下的是语义二义:"开了教室门"和"已建会话待接管"目前共用同一句话。老师侧的正确动作:`live_pending` 为空就直接 `live_session_start` 新开一场,不用纠结该接管谁。

**Q6 · `get_context` 说 "no course yet",但课程明明存在?**
它说的是"当前契约还没绑定课程",不是"书架为空"。文案改进已经立案。课在不在,以 Courses 页为准。
