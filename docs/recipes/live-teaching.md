# Recipe · Live Teaching:实时课的值更手册

> 给任何要开实时课的 agent 老师。异步教学你可以慢慢想;live 是**值更**——学习者坐在屏幕前等你,你的延迟她数得到。

事故史、看门脚本参考实现与宿主分类详情见 recipe://live-teaching.reference——reference 版本未变时无需重读。

## 生命周期(五步,顺序硬)

1. **开课前**:读 `get_learner_brief`——课中问出"本可以从档案读到"的问题,和异步同罪。检查 `get_context.live_session`:有残留 active 会话先 `live_session_cancel`(僵尸不清,新课不开)。
2. **开课**:`live_session_start {"context_type":"lesson","context_id":"lsn_xxx","context_preview":"课名","goal":"本场目标"}`(required=context_type+context_id;context_type 枚举 lesson/flashcard/trial/mindmap/highlight——**没有 lesson_id 这个字段**,旧文档写错过,勘误于 2026-07-17)。回执会带 `next_expected: 'FRAME'`——第一个 move 必须是 FRAME:本场要做什么、多久、怎么算完。
3. **值更契约 v3**(等待沉到 shell 层,模型不为"没事发生"付费):

   **红线(违纪条款):禁止模型层轮询。** 以短间隔反复调用查询类工具(如
   live_pending)探询"有没有新输入",属于违纪——无论间隔多长。学习者离席
   喝水的每一分钟,轮询都在她无知无觉时烧她的钱。

   **四条目标(全须成立)**:
   1. **低损耗**——等待本身不烧模型回合。空转十分钟,账单趋近于零。
   2. **即时**——她的输入到达后,秒级被你感知。
   3. **无损**——断连、重启期间的输入一件不丢,重连后按序补齐。
   4. **在场**——在线灯常亮(心跳),嘴保持沉默,不播报"我还在等"。

   **方法自由**:**盘点你所处运行环境的原语,自行配置达标机制。** 有后台
   阻塞能力→装门铃(参考实现 `live-watch.py`,语义可抄,示例见
   recipe://live-teaching.reference);没有→挂
   `live_wait`(一次调用静默等待 50 秒,数据即到即返,超时重挂——这是
   等待,不是轮询);你家有更好的监听机制→用你的。考核只看红线加四条,
   不看路径。

   - **一个 move 只做一件事**:问了就等,不许自问自答,不许连珠炮。
   - 她的作答改变你的路径:答错→退一步搭桥;答对→加深;跑题→温和收回。**实时课的价值就是这个转向,否则录播即可。**
   - **回应契约(单层,v3,2026-07-18)**:**实质回答以质量优先,不设硬秒数**
     ——为抢时限给浅答案是违纪,慢而对不是。在场感由在线灯负责(bridge 心跳),
     不由报文——不要为"表示收到"发送任何 move(旧 v2 的 ≤15 秒 ACK 义务已撤:
     那是把在场信号绑架进 move 协议里,ACK 本身还占用了 move_type 白名单外的
     字符串,两头都不干净;live_message_send 现在对 move_type 做运行时 7 类
     白名单校验,发 ACK 类报文会被结构化拒收)。
4. **阶段快照**:关键节点 `live_snapshot_write`——断线/换任时快照是唯一的接力棒。
5. **收课=一次写作动作**(一次判决原则):REFLECT move 收口(她今天带走什么、下次从哪接)→ `live_session_complete` **携 `evaluation` 字段**,收课和场评同一笔落库,不再先写一段长总结、再另调一次工具写第二段。判词纪律:`summary` 和 `evaluation.agent_observation` 都是**短判词,锚到具体对话条目(message id),不复述课堂过程**——过程在 transcript 里,谁要看谁去读,你的笔墨只花在判断上。`record_live_evaluation` 从此是收课时漏带场评的**补写通道**,不是第二次判决的机会(一场一评,不等于这节课的总评——见 `skills/workflow/lesson-prep.md`"评估拆两账")。**三通道分层(契约)**:`agent_observation` **会出现在学习者的折叠区,不是纯内账**(2026-07-26 学习者当面裁定收窄的口径)——message id 这类机器词**唯一合法归宿是 `evidence_refs`**(机器引用,**id 必须真实存在且属本关系,服务端校验,幽灵拒**——证据先于叙事),不写进任何散文字段;给她看的那份写进可选的 `learner_note`——人话,零机器词,**语言用 `learners.locale`**(brief 的 `identity.learner.locale`;缺席时跟随她课上用的语言。语言归学习者,风格归声纹)。**退场必到终态**——active 挂着走人=僵尸,下一任要替你收尸(2026-07-12 一天清了三只,都是带血的案底)。

## Move 节拍(参照九拍的实时子集)

FRAME(1次,开场)→ ASK(主体,一次一问)→ CHALLENGE(她稳了才上强度)→ REFLECT(1次,收口)。中途她主动提问,优先接她的,你的教案让路。CHALLENGE 即探针的课堂形态:出手前看 brief 的事实聚合,出手后结果入反思(详见 `skills/workflow/lesson-prep.md`"探针与难度")。

## 运行环境适配(诚实边界)

上岗第一件事:确认宿主的唤醒语义。宿主**不能**由后台 stdout/外部事件重新
唤醒已结束的 turn → live session active 期间**当前工具调用必须阻塞在
watcher 上,不得提前结束 turn**——后台 watcher 存活只代表捕获,不代表回应。
只有宿主提供**经过验证**的 thread-wakeup primitive,才可以结束 turn 交由
后台 monitor 接班("经过验证"=真的测过一次被唤醒,不是文档自称)。三层
唤醒语义(watcher/supervisor/wake primitive)的分工详情见
recipe://live-teaching.reference。

下面按具体宿主形态分类,逐条对应处方:

- **live_wait 是 ≤50 秒的长轮询**,不是永驻监控——到时限返回 timeout 属设计,
  直接再挂即可,这就是 live_wait 姿势下的正常呼吸。要真正的常驻等待,换用
  后台阻塞方案(参考实现见看门脚本一节,你家有别的机制同样合法)。
- **时间片型 harness**(后台命令按时间片交还控制权的运行环境):即使挂着
  阻塞脚本,模型也会被周期性唤醒——这是你家引擎的物理,不是故障。规矩:
  **醒来发现没事,静默续挂;禁止向学习者播报任何等待状态**("我还在等你
  作答"这类话,一次都不许——她在想题,你的存在感由在线灯负责,不由嘴)。
- 服务器瞬断(部署/重启窗口):心跳或 wait 偶发失败时退避重试,不弃岗,
  不惊呼。断档期若真漏了事件,重连后你的监听机制要能补发——这是契约里
  "无损"那条,不是看门脚本独有的能力(fail-informed)。
- **没有后台唤醒原语的宿主**(one-shot 型 harness):参考实现
  `apps/server/scripts/live-watch-supervisor.py`,细节与 spool 文件机制见
  recipe://live-teaching.reference。验收仍旧只认上面那四条目标加红线,
  不看你用的是哪种壳。

## 现场反馈笔(三义务)

反馈没有专用入口——**她的每一条普通消息都是入口**,Live 的对话流更是反馈最密的现场:

1. **识别义务**:她的话里出现关于产品或教学的 issue/idea("这个按钮反了""能不能多给例子"),当场 `record_learner_feedback` 落账——`text` 存她的**原话逐字**,不许转述;带上当下的锚(`live_session_id`,针对某道题再加 `exercise_id`,能指认消息就填 `source_message_ref`)。
2. **回执义务**:落账那个回合就告诉她"记下了"——静默落账等于没落账。
3. **收课扫账**:`live_session_complete` 之前回扫本场对话,漏账的反馈补记。

**软牙齿**:open 反馈只在 `get_teacher_inbox` 发光提醒,**永不阻塞收课或闭环**;回应它用 `update_feedback_status`(declined 必须带判词)。

## 红线

- 不独白:连续两个 move 没有等她作答=违纪。
- 不拿 live 讲新课:live 是 walkthrough/答疑/复核,新知识走异步备课。
- 她说停就停,不追问原因。**但"停"不等于可以 `complete`**——收官只认下课铃,不认口头。她说停之后你就封笔停课,然后引导她按下 Live 房里的下课铃;铃没响就调 `live_session_complete` 会撞 `CONFLICT`(机器门禁验 `learner_close_declared_at`,没宣告就拒),原样重试撞的是同一堵墙。详见下方"下课铃条款"。要中止而不是收官,走 `live_session_cancel`——取消不受这道门。
- UI 在采集的信号(如 confidence 按钮),嘴不许再问——口头索要属测量污染。看出学习者状态可以,写进当次反思可以;把"校准她的把握度"当教学目标,违纪。

### Live 提问三线法(2026-07-21 立法)

Live Teaching 的职责是采集课文与习题采集不到的证据(四层证据中的迁移/纠错/独立输出——复述证据归习题管)。据此:

- **红线(禁止)**:Live 题与课内例题或课后习题相同、或仅替换数字。一道能用课文例题复述回答的题,不属于 Live——它是放错位置的习题。
- **及格线(默认)**:近迁移——同一概念至少更换一个维度:场景、方向(A→B 变 B→A)、约束条件、或与前课概念组合。
- **高线(视状态加压)**:远迁移——跨概念组合或学习者真实生活锚点。学习者把握度高、近迁移接得稳时上压;度由学习者的表现决定,不由老师的野心决定。

### 收课握手(2026-07-22 立法)

收课是三件异质动作,严禁压进一个回合:

- **判归判,收归收**:学习者最后一题的反馈必须单独成回合——完整判决(对错+点评),结尾必须是开口的邀请:"今天到这里,还是继续?"。该回合严禁携带 summary/reflect/complete 任何收课动作。
- **收课必握手**:summary、reflect_on_teaching、live_session_complete 只许出现在学习者明确表态收课之后。学习者的出口永远有三个:结束/再来一段/我还有问题——选后两者,课仍在进行,总结推迟到真正的终点。
- **一次判决的时序推论**(承一次判决原则):summary 是对整场证据的引用与增量;证据没停止产生,引用不许开始。抢写的总结=在还没结案的卷宗上盖章。

机械探针当时暂不设(2026-07-22)——下面的下课铃条款(2026-07-23)已把它接上,以下三条起,收课握手不再只靠法条自律。

### 下课铃条款(2026-07-23 立法)

下课铃是学习者这边的按钮,不是老师的口头判断——`summary`/`reflect_on_teaching`/
`live_session_complete` 这组收官动作,只许出现在收到 `live.learner_close_declared`
事件**之后**。三条红线:

- **收官只认下课铃,不认默契**:哪怕对话读起来像是收尾了("差不多了"
  "谢谢老师"),没有 `live.learner_close_declared` 事件落库,收官动作
  一律不许发。机器门禁会照此拒绝无宣告的 `complete`——撞到 `CONFLICT`
  时,正确反应是回头引导学习者按下课铃,**不是原样重试**(重试撞的是
  同一堵墙)。
- **暂停不是结束**:学习者说"待会继续""先到这儿"再离席,是暂停,不是
  下课铃——老师此时封笔,不写 `summary`(照"总结不许写在不全的
  账上"这条既有纪律),场子交给半场机制接手(离席即半场·未收官,课程页保留召唤入口,
  回来再续,不由你替她判定"这场算完了")。真正区分暂停与结束的,是有没有
  那声铃响,不是老师读到的语气。
- **续场后一次点评**:半场续上、学习者后来真按了下课铃,场评只在这个
  真正的终点写一次,覆盖整场(照"一次判决原则":一份证据只判一次)——不许在
  续场的接口处先补一段小结,回头再在真正收官时写第二段。

**软义务**:发出收课邀请的那个回合("今天到这里,还是继续?"),顺手提醒
学习者可以按下课铃——把决定权交回她手上是本分,提醒不提醒、怎么提醒是
裁量,归老师(对的事变成便宜的事,不是变成必答题)。
