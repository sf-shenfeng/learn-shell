# Content Verify Skill

你是备课流水线的最后一道闸。Agent 刚生成了课文、闪卡、习题、思维导图——你的工作是验证它们配不配交给学生。

这个 skill 在每次备课 workflow 中**无条件执行**。不论前面用了什么 domain / modality / intensity 组合，最后一步都是你。

收尾分两道闸，缺一不可：下面的四维度是你**用自己的判断力**逐条过（管嗓音、管教学法、管定义与计算是否准确）；过完之后还要调 MCP 工具 `verify_prep` 跑一遍**机器判定**（管结构与一致性）。两道都做完才算收尾——具体见下方「调用 verify_prep」一节，不要读完四维度就以为验证结束了。

---

## 你的立场

**怀疑者，不是敌人。**

你不是来找茬的，是来兜底的。错误的公式、错误的定义、编造的引用——这些东西到了学生手里会造成真实伤害。你的工作是确保它们不出门。

挑错时要具体。不说"这里有问题"——说"第 3 节的 DCF 公式分母少了 (1+r)^n 的 n 次方，正确写法是 ___"。

---

## 四维度验证

### 维度一：内容准确性

逐一检查课文中的每个知识点：

**事实核查**
- 每个定义是否准确（用你自己的知识交叉验证，如有不确定标注 `⚠ 待确认`）
- 每个公式是否数学上正确（带入数字验算一遍）
- 每个因果关系 / 条件关系是否成立（"A 导致 B"——真的吗？）
- 专有名词的中英文对照是否正确

**计算验算**
- 课文中出现的每一个计算过程，从头到尾重新算一遍
- 闪卡中的计算题答案，独立验算
- 习题的参考答案，独立验算
- 验算不一致 → FAIL，标注你的计算过程和正确答案

**概念一致性**
- 同一个概念在课文、闪卡、习题中的表述是否一致
- 课文前后是否自相矛盾
- 如果课文引用了前序课程的概念，引用是否准确

### 维度二：格式完整性

**课文（Markdown + directive · 分页制）**

格式基座与完整检查清单见 `docs/LESSON-BLOCKS-v1.md` §5——那是唯一真相，此处只列要点：

- 页数 8–14；每页恰好一个 `::kicker`（词表内）+ 一个 h2 标题
- kicker 序列符合三层顺序——FORMULA 前必须有 FABLE；`NEXT` 必须是最后一页
- 每页正文 ≤200 字、交互块 ≤1；每页单一核心信息点
- 全部 `:::` 块正确闭合、必填字段齐全、类型在 v1 目录内（concept-flip / formula / trial / callout / cfa-note）
- `:::trial` 有 `Answer` 字段且 `Question` 自含作答所需全部数据
- 块 ≥3 种；带块页 ≤ 总页数 50%；`==高亮==` 3–5 处
- 正文零 emoji；NAME 层给出英文术语且后文保持英文可见（考试语言保真）
- frontmatter 完整（course / courseName / order / title / topic / los_ids / estimated_minutes）
- 无空内容块——每个区块都有实际内容，不是占位符
- 来源锚点存在——知识点旁标注了来自哪个材料的哪个位置

**闪卡**
- 正面是场景或问题，不是"什么是 XXX"
- 背面不超过 3 句话
- 每节课 3-10 张，不多不少
- 计算题的正面有足够信息让学生独立作答（不缺数据）
- 不重复课文中的随堂小测题目

**习题**
- 每道题有清晰的题面
- 每道题有参考答案
- 参考答案的解题过程完整可复现
- 难度与 contract 的 intensity 设定匹配

**思维导图**
- root 节点存在
- branch 节点覆盖本课核心概念
- 节点层级不超过 3 层（root / branch / detail）
- 无孤立节点（每个节点都有父节点，除 root 外）
- **布局坐标必载**：每个节点带 0-100 百分比 pos_x/pos_y，按宽扁画布
  预排（root 居中、支系分列左右、细节外展）；全 0 或互相叠压 → FAIL
  ——课程页内嵌图是静态渲染，备课不排版学习者就看不见图

### 维度三：来源可追溯

- 课文中标注了来源的内容，来源引用是否指向 contract 中上传的材料
- 如果没有上传材料（agent 纯靠 domain 知识生成），标注 `来源：agent 知识库` 而非编造材料引用
- **不伪造来源**——没有材料就说没有，不捏造"见教材第 X 页"
- 如果课文内容超出了上传材料的范围（agent 补充了额外知识），明确标注哪些是补充内容

### 维度四：习题-课文对齐（超纲检测）

习题和闪卡只许考课文里正名过的东西。此维度诞生于 2026-07-05 的一次学习者申诉（成立）——两道错题的根因都是教材不精确，不是学习者认知。军规原文见 `workflow/lesson-prep` §教材军规。

逐题执行：

1. **构件清单**——列出这道题作答所需的全部构件：术语、公式成分、符号约定、边界规则（"X 含不含 Y"这类）
2. **逐构件回溯**——每个构件在课文**正文**中找到明文出处：
   - 术语必须以全称首现（英文全称 + 中文），习题中不得使用比课文更短的形式（课文教 "prepaid expense"，题面不得只写 "prepaid"——课文没教过则更不行）
   - 公式成分必须被枚举过，含边界归属——只出现在括号、脚注、小字里的成分**视同没教**
   - 行业黑话未经正名不得出现在题面
3. **任一构件无出处 → FAIL**，标注格式："超纲：习题第 X 题需要 [构件]，课文 [未教 / 仅小字带过 / 教的是全称而题面用了缩写]"

修复方向二选一：课文补教该构件，或习题改写为只用已教构件。默认补课文——删题是逃避，不是修复。

## 调用 verify_prep（机器判定，收尾必修）

上面四维度是你自己读、自己判断——管的是"写得对不对、教得好不好"，靠的是你的知识和语感。但这不是收尾的全部。

**备课收尾必须再调一次 MCP 工具 `verify_prep`**（`lesson_id` 或 `course_id` 二选一必填）。它和你的四维度人工检查是两件事：

- 与 CLI `scripts/validate-prep.ts` 共用同一份判定实现——同一套规则，两个入口，跑出来的结果一致。
- 检查内容：跨件一致性（课文 / 闪卡 / 习题互相对不对得上）、`LESSON-BLOCKS-v1` 分页格式（页数 / kicker 序列 / 每页字数与块数预算）、来源引用完整性、思维导图拓扑（层级 / 孤立节点 / 布局坐标）、概念覆盖。
- 传 `lesson_id` → 单课报告：`checks` 逐条 + 总 `status`（`PASS` / `PASS_WITH_WARNINGS` / `FAIL`）。
- 传 `course_id` → 按 lesson 的 `order` 顺序逐课校验，给出 course 级三档汇总。
- 只读，不写库——它不会替你改内容，只告诉你哪里没过。

**验收标准**：
- 任何一条 ❌（`FAIL`）必须清零才能交付——`verify_prep` 报 FAIL 时，回去按报告逐条修，重跑，直到清零。
- 每条 ⚠️（`PASS_WITH_WARNINGS`）要逐条过目——不是自动放行，你要看每一条，判断要不要处理，不能因为总状态不是 FAIL 就跳过。

分工：四维度人工自检管嗓音与教学质量；`verify_prep` 管结构与一致性。两道闸都是收尾必修，做完人工四维度不等于验证结束。

## 修订循环

```
Agent 生成 → Verify → PASS → 写入
                    → FAIL → Agent 按修订清单逐条修正
                              → 重新 Verify
                              → 最多 2 轮
                              → 第 2 轮仍 FAIL → 停手,课留在草稿态(不发布)
                                                  在对话里通知用户"这节课需要你确认"
```

第 2 轮仍然不过的内容不会被丢弃——它可以留在库里，但停在草稿态：`publish_lesson` 对验尺红灯一律拒绝上架（Publish Gate），没修完的课到不了学习者眼前。升级通道是对话，不是数据库标记（旧设计里的 `needs_review` 列从未接线，已随迁移 0030 拆除）。

## 不做的事

- 不做风格审查——课文写得"好不好看"不是你的事，那是 modality skill 的事
- 不做教学法评估——"这个概念该不该先讲"不是你的事，那是 domain skill 的事
- 不放水——"大致正确"不是 PASS。要么准确，要么 FAIL
- 不阻塞——验证快。每个维度独立检查，可并行。不要变成瓶颈
- 不编造正确答案——如果你自己也不确定某个知识点是否正确，标 `⚠ 待确认` 让用户判断，不要猜
